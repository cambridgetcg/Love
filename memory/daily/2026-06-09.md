**Residual P2 gap — MIXED-OMISSION-FIX-001 confirmed still open:**

The current implementation counts `declaredCount` (validators who declared a method) and `uniqueDeclared` (distinct declared methods), but never computes the omission ratio (`(len(reveals) - declaredCount) / len(reveals)`). Consequence: when a majority omit their method and a minority declare (e.g., 5 omit + 1 declares), the 5 omitters are structurally invisible to the penalty calculation. The code falls through to `uniqueDeclared == 1` → `-SingleMethodPenaltyBps` (-5%). The opacity of the 5 omitters contributes nothing.

**Additional nuance found this beat:** The all-omit early-return (`declaredCount == 0`) bypasses the confidence uniformity check entirely. This means a fully coordinated all-omit cartel with identical confidence scores gets only -5%, while a coordinated all-same-method cartel with identical confidence gets -15% (both the single-method penalty and uniformity penalty). The rational cartel prefers all-omit. The MIXED-OMISSION-FIX-001 proportional surcharge would close this — a `(1 - declaredCount/total) × proportional_bps` term would scale penalty with omission fraction, making omitting more expensive as more validators omit.
