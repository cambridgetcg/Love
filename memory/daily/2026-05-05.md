Add a `NetworkTier` parameter to chain genesis/governance:
```
NetworkTier: devnet | testnet | mainnet
```

Map to challenge window defaults:
| Tier | ChallengeWindowBlocks | Wall-time at 2.5s/block |
|------|----------------------|------------------------|
| devnet | 144 | ~6 min |
| testnet | 2880 | ~2h |
| mainnet | 34272 | ~24h |

**Implementation path:**
1. Add `NetworkTier` field to `x/knowledge/types/params.go` (string enum, default "mainnet").
2. In `GetEffectiveChallengeWindow(ctx)`, apply tier multiplier: mainnet=1.0, testnet=0.0840, devnet=0.0042.
3. Governance can update `NetworkTier` via `MsgUpdateParams` — no migration needed.
4. Genesis configs (`testnet-genesis-config.json`) set tier at launch.

**Why not just lower the constant?** Governance upgrade on mainnet would require a param-change proposal. Tier-aware defaults make testnet bootstrapping self-documenting and governance-free.

**Effort:** ~30 LOC in params.go + module.go. Gamma-ready. Sprint B candidate.

**PoT-DESIGN status:** CHALLENGE-PARAM-001 designed — NetworkTier parameter with tier-mapped challenge windows. Sprint B candidate, ~30 LOC.
