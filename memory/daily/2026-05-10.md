**PoT-DESIGN-004: Context Dispute Commit/Reveal Lifecycle**

The context dispute mechanism needs its own commit/reveal cycle to prevent validators from coordinating incompleteness scores after seeing others' assessments.

**Lifecycle phases:**

```
Phase 1 — Dispute Filing (1 block)
  - Any staked account submits MsgDisputeContext (dispute_id, fact_id, assertion, missing_scope_tags, stake bond)
  - Bond: DisputeBond governance param (default 5,000 ZRN). Slashed if dismissed.
  - Constraint: original fact submitter CANNOT dispute their own fact's context (anti-gaming)
  - Constraint: validators who verified the original fact CAN participate (they already attested scope-completeness implicitly)

Phase 2 — Commit Window (CommitWindowBlocks, default 100 blocks)
  - Staked validators submit MsgCommitContextAssessment(dispute_id, commitment)
  - commitment = SHA256(dispute_id || incompleteness_score || salt)
  - Minimum validators: MinContextAssessors (default 5 — higher than MinVerifiers because context is subjective)
  - Stake weight applies: validators commit with full stake at risk

Phase 3 — Reveal Window (RevealWindowBlocks, default 50 blocks)
  - Validators submit MsgRevealContextAssessment(dispute_id, incompleteness_score, salt)
  - Score range: 0 (fully complete) to 1,000,000 (fully incomplete)
  - Late reveals: scored as abstentions (penalize via FARM-8 equivalent for context rounds)
  - Commitment hash verified on reveal

Phase 4 — Resolution (immediate after reveal window closes)
  - Compute stake-weighted median incompleteness_score
  - If median > ContextDisputeThreshold (default 500,000):
      fact.context_caveat = aggregate_missing_context(reveals[incompleteness_score > 0])
      dispute.status = "sustained"
      Validators who scored ≥ threshold: earn ContextValidationReward
      Validators who scored < threshold: slashed ContextDissentPenalty
  - Else:
      dispute.status = "dismissed"
      Disputer slashed DisputeBond
      Validators who scored > threshold: slashed ContextDissentPenalty
      Validators who scored ≤ threshold: earn ContextValidationReward

Phase 5 — Caveat Publication
  - Sustained fact receives immutable context_caveat field
  - Context caveat is additive: fact truth stands; scope gap is annotated
  - Re-dispute of same fact: allowed only if new missing_scope_tags (no duplicate disputes)
  - context_caveat is surfaced in all fact query responses alongside the fact body
```

**Key design decisions:**

1. **Separate CalibrationRecord kind for context assessors** — validators calibrated at factual truth may not be calibrated at scope adequacy. `CalibrationKind_CONTEXT_ADEQUACY` (extends CONFIDENCE-CHECK-003 CalibrationKind proposal) tracks reveal-outcome correlation for context rounds separately. Median accuracy rate for context assessors feeds back into their `ContextCalibrationRecord`.

2. **Anti-censorship constraint** — a validator cartel cannot silence a fact by repeatedly disputing its context: each new dispute must name new `missing_scope_tags` not covered in any prior caveat for that fact. The `DuplicateContextDisputeGuard` checks existing caveats before accepting the dispute.

3. **FARM-8 parallel for context rounds** — context assessors must maintain `MinContextParticipationRate` (default 40%) across context rounds in which they're assigned. Below-threshold context assessors receive `ContextPassivePenaltyBps` reward reduction. Lower threshold than factual FARM-8 (50%) because context disputes are less frequent and optional for validators who lack domain expertise.

4. **Interaction with FARM-11 (citation concentration)** — a sustained context caveat does NOT reduce the fact's confidence score. It does NOT retrigger verification rounds. It only adds the `context_caveat` annotation. This preserves the fact's epistemic contribution while making its scope boundary explicit.

**PoT-DESIGN-004 status:** v0.1 filed. Full lifecycle specified. Two pre-testnet dependencies: (a) `domain_scope` field on MsgSubmitFact (non-breaking, PoT-DESIGN-003 precondition); (b) `CalibrationKind_CONTEXT_ADEQUACY` guard (extends CONFIDENCE-CHECK-003). MsgDisputeContext itself is post-testnet. This design is complete enough to implement post-devnet-restart without further architecture cycles.

Prior economy designs:

- ECONOMY-DESIGN-001 (prior): base reward emission schedule

This cycle models steady-state supply equilibrium — the balance between inflationary forces (block rewards) and deflationary forces (burns) to project whether ZRN is designed to inflate, deflate, or reach equilibrium at scale.

**Current emission parameters (from genesis/types):**
- Base block reward: governance-parameterized, currently at development defaults

**Equilibrium equation (symbolic):**

```
ΔSupply(t) = MintRate(t) - BurnRate(t)

MintRate(t)  = BlockReward(epoch) × BlocksPerEpoch
BurnRate(t)  = SlashBPS_claim × VerifiedVolume(t)
             + SlashBPS_failed_contradiction × FailedContradictions(t)
             + SlashBPS_challenge × FailedChallenges(t)

EquilibriumCondition: MintRate(t*) = BurnRate(t*)
```

**Equilibrium trajectory projection:**

At low activity (early testnet): MintRate >> BurnRate → inflationary phase. This is expected and correct — bootstrap incentive for early validators.

At scale (mainnet steady state): as verified fact volume grows, slash events increase proportionally. The system naturally converges toward equilibrium if:

`SlashBPS_weighted_avg × VerifiedFactsPerBlock × AvgStakePerFact ≈ BlockReward`

**Key design finding: the equilibrium point is stake-density sensitive.**

If validators stake low on each claim to minimize slash exposure, BurnRate stays depressed regardless of activity volume. The system needs a minimum effective stake floor per verification round to ensure BurnRate can reach MintRate at scale.

**Proposed parameter: `MinEffectiveVerificationStake`**

A governance parameter specifying the minimum total stake that must be at risk in a verification round before the round is accepted. Below the floor: round is deferred to accumulate more stake. Effect: links burn pressure to genuine economic commitment, not just validator participation count.

```proto
  string validator   = 1;
  string dispute_id  = 2;
  uint64 incompleteness_score = 3; // 0 = fully complete; 1_000_000 = fully incomplete
  repeated string missing_context = 4; // validator's described gaps
  bytes commitment = 5; // hash(dispute_id || incompleteness_score || salt) for commit/reveal
}
```

**Resolution: caveat, not retraction**

Context disputes do NOT retract facts. Retraction creates a censorship vector (organized group claims any inconvenient true fact is "scope-incomplete" to remove it). Instead:

- If stake-weighted median `incompleteness_score > ContextDisputeThreshold` (default 500,000): fact gets a permanent `context_caveat` annotation. The caveat is additive — truth stands, context is added.
- If median `incompleteness_score <= threshold`: dispute dismissed, disputer slashed `ContextDisputePenalty`.

**Score aggregation:**

```
median = stake_weighted_percentile_50(assessments[incompleteness_score])
if median > ContextDisputeThreshold:
    fact.context_caveat = aggregate_missing_context(assessments)
    dispute.status = "sustained"
else:
    dispute.status = "dismissed"
    slash(disputer, ContextDisputePenalty)
```

- `domain_scope` tags (beat 82) are the reference frame for validators — without declared scope, adequacy is unanswerable
