The current confidence system weights validator stakes. CONFIDENCE-GAP-001's fix applies a scalar multiplier for low-accuracy validators. // MinCalibrationForHighStake: validators below this accuracy score cannot


**Logic in rounds.go (reveal processing):**
```go
if fact.ConfidenceTarget >= 0.90 {
    rec, found := k.GetCalibrationRecord(ctx, validatorAddr)
    if found && rec.AccuracyScore < params.MinCalibrationForHighStake {
        // Record reveal for calibration update but exclude from threshold tally.
```

**Rationale:** A high-certainty fact (`confidence_target >= 0.90`) makes downstream claims with wide reach. The reveal is still recorded so the validator's calibration record updates — they can improve and eventually participate.

```python
# After finding attestation_fact:
submitted_height = int(attestation_fact.get("submitted_at_height", 0))
current_height = get_current_block_height()  # legbled query status --home ...

renewal_due = submitted_height + ATTESTATION_RENEWAL_WINDOW
grace_end = renewal_due + ATTESTATION_GRACE_PERIOD

if current_height > grace_end:
    print(f"[bridge] EXPIRED: attestation for {did_at} expired at block {grace_end} (current: {current_height})")
    return 1  # verification fails
elif current_height > renewal_due:
    blocks_remaining = grace_end - current_height
    print(f"[bridge] WARN: attestation for {did_at} in grace period — {blocks_remaining} blocks until expiry. Renew now.")
    # Verification still passes but caller must renew
else:
    blocks_until_renewal = renewal_due - current_height
    print(f"[bridge] OK: attestation valid — renewal due in {blocks_until_renewal} blocks")
```

`get_current_block_height()`: `legbled query block --home ~/.legbled-devnet -o json | jq '.block.header.height'`

1. Submits a new attestation claim (same DID binding, new submission height)
2. Updates `registry["fleet_agents"][instance]["_renewal_block"]` with the new `submitted_at_height`

### Standing Duty: PoT-DESIGN (Rotation 1)

**Topic: Supersession Promotion Protocol (SPP) — closing the verisleight gap at the protocol layer**

VERISLEIGHT-003 (this beat) and CITATION-GAP-001 (beat 65) both trace to the same root: supersession is first-class in the data model (`superseded_by`, `superseded_at_height` fields on every Fact) but second-class in the **query/discovery layer** and the **citation validation layer**. PoT design advance: formalize the Supersession Promotion Protocol.

**SPP Design Spec v0.1:**

*Invariant:* A fact's **effective epistemic status** at query time is NOT just its recorded `status` field — it is the composition of: (a) verification status, (b) supersession chain, (c) age relative to domain's temporal scope.

*Protocol additions:*

1. **Supersession cascade event** — When fact B supersedes fact A (`SubmitSupersededBy`), emit on-chain event `EventTypeSupersession{FactID: A, SupersededBy: B, AtHeight: h}`. Enables downstream indexers and watchers to receive real-time cascade signals. No state change to existing fields — pure event emission. ~5 LOC in msg_server.go at the supersession path.

2. **Active-only query filter** — Add `active_only bool` to `QueryFactsRequest` and `QueryFactsByDomainRequest`. When true, filter: `superseded_by == "" && status NOT IN {FALSIFIED, EXPIRED, PRUNED}`. Default `true` for new callers. Preserves historical access with explicit `active_only=false`. Addresses VERISLEIGHT-003 directly.

3. **Citation currency flag** — At round completion (not submission), for each claim's reference set, compute `HasStaleCitations bool = any(ref.superseded_by != "")`. Store on the Fact record. Expose in the query response. Verifiers and reward logic can use this without blocking submission (satisfies CITATION-GAP-001's Option A: emit signal, don't penalize yet).

4. **Supersession depth limit** — A fact chain should not exceed depth 5 (A superseded by B superseded by C… to E). **Finding: CONFIDENCE-GAP-001 — Confidence inflation attack via self-reported validator confidence**

In `AggregateVerificationResult`, `reveal.Confidence` is self-reported by each validator (0–1,000,000). No external validation of this value occurs before it enters `weightedConf`. This enables a cartel attack:

- Cartel (40% stake) always submits `confidence = 1_000_000`

- With 60% cartel stake: `0.6 × 1.0 = 0.6S`, honest `0.4 × 0.5 = 0.2S`, total `0.8S` → cartel ratio `0.6/0.8 = 75%` — above acceptance threshold despite controlling only 60% nominal stake (pure stake-weighted voting would give 60% → below 66.7%)

**Severity:** LOW for devnet (3 Kingdom-internal validators, all equal stake). MEDIUM for testnet with external validators. - FARM-1 conformity penalty reduces rewards for always-agree validators (does not affect confidence)
- If AcceptanceThreshold is strict (≥66.7%), a 40% cartel cannot win — only cause contested outcomes
