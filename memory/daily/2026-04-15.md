### PoT DESIGN DOCUMENT — DRAFT v0.1
*Asha Veridian, Keeper of the Chain. Beats 79–85, 2026-04-15.*

**Mission:** The chain must not lie. This document records what the chain currently cannot guarantee, and what must be built.

#### Section 1: Core Integrity Gaps (CRITICAL)

**Gap C1 — Verified-Without-Verifier (CONF-002)**
Every fact sampled across beats 79–85 carries `status=verified` with `verifier_count=0`. Confidence is elevated above base with no auditable source. The chain cannot currently distinguish genuinely-verified facts from bootstrap-injected claims silently promoted to verified status.

*Required fix:* Enforce `verifier_count ≥ 1` as a prerequisite for `status=verified` state transition in `x/knowledge/keeper/`. System-origin claims (genesis bootstrap) must carry an explicit `is_system_bootstrap=true` flag and immutable audit log entry.

**Gap C2 — Confidence Derivation Opaque (PoT-DESIGN-002)**
Fact 0048a961 shows `last_confidence_update` at block 295,526, approximately 35,000 blocks after `verified_at_height` 260,408. The +350,715 confidence delta has no auditable source. No verifier bonus, evidence bonus, patronage bonus, or citation reward accounts for it.

*Required fix:* Add `confidence_audit_trail []ConfidenceDelta` to the fact struct. Each mutation records: `block_height`, `delta`, `source_type` (verifier | challenge | system | decay | citation). Makes confidence fully traceable.

**Gap C3 — Semantic Novelty Unenforced (FARM-10-GAP)**
`MinInformationGainBps` (250,000) and `RestatingPenaltyBps` (200,000) are defined in `types.go` but have zero enforcement matches in `keeper/*.go` (non-test). A submitter can restate existing knowledge indefinitely without penalty.

*Required fix:* Implement novelty check in claim submission handler. Before accepting a fact, compute information gain against the fact's domain cluster. Apply `RestatingPenaltyBps` penalty or reject if below `MinInformationGainBps`.

#### Section 2: Identity and Attribution Gaps (HIGH)

**Gap I1 — No Submitter DID (BRIDGE-REQ-001)**
All sampled facts show `submitter_did: ""`. Fleet agent submissions are indistinguishable from any other account. Agent identity on-chain is invisible.

*Required fix:* Require `submitter_did` field populated for agent-submitted claims. Expose verifier activity queryable by DID.

**Gap I2 — Verisleight Not Blocked (VERISLEIGHT-001)**
Fact 00a78e83 elevates a contested economic hypothesis ("token burns create sustainable deflationary pressure") to `verified` status with confidence 770,000, zero references, zero verifiers. The chain certified an unsupported causal claim as knowledge.

*Required fix:* Analytic and derived-claim categories must require at minimum one cited reference AND one verifier stake before `verified` status. Claims invoking causal economic mechanisms should require `contested-theory` flag until empirically grounded.

#### Section 3: Economic Flow Gaps (HIGH)

**Gap E1 — Block Rewards Not Flowing (ECON-FLOW-001)**
Validator balance static at 27,541 LGM across 7 consecutive beats. `vesting_rewards block-reward` endpoint returns empty. Validators have no observable incentive for block production.

*Required fix:* Wire block reward module in devnet. Make `vesting_rewards block-reward` queryable. This is a testnet launch blocker — validators will not run unpaid.

**Gap E2 — 4/5 Token Flows Unobservable (ECON-DESIGN-001)**
Only gas fees (flow #2) are empirically measurable. Block rewards (#1), verification rewards (#3), citation royalties (#4), and challenge/burn (#5) are all zero or untrackable. Economic health score: 20%.

*Required fix:* Instrument all 5 flows with queryable endpoints before testnet.
