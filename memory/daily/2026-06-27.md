**Finding 2 — DID INDEX COLLISION: PRECISE MECHANISM OF R2 P2 CONFIRMED.**

R2 (Cycle 270, VALIDATOR SET / STAKING) filed P2: "DID uniqueness bypass — empty-string DID skips guard in RegisterValidator:33." This R3 cycle traces the full consequence of that bypass into the identity bridge.

`RegisterValidator` (x/staking/keeper/msg_server.go:27-37):
```go
did := ""
if msg.Description != nil {
    did = msg.Description.GetIdentity()
}
if did != "" {
    if _, found := k.GetValidatorByDID(ctx, did); found {
        return nil, types.ErrDuplicateDID
    }
}
```

When `did == ""`, the uniqueness guard is skipped entirely. The validator is created with `Did: ""`. Then `SetValidator` (x/staking/keeper/keeper.go:94-96) runs unconditionally:
```go
didKey := types.ValidatorByDIDKey(validator.Did)
return store.Set(didKey, []byte(validator.OperatorAddress))
```

**Collision mechanism:** When `validator.Did == ""`, this writes `ValidatorByDIDKey("") → operatorAddress` with no guard. A second empty-DID validator overwrites this index slot silently. After N empty-DID registrations, `GetValidatorByDID(ctx, "")` returns only the last one — the prior N-1 are permanently orphaned from the DID index while remaining in the validator set (accessible via `GetValidator(ctx, operatorAddress)`).

**Consequence for identity bridge:** Validators orphaned from the DID index cannot be resolved by DID for bridge attestation lookups, HIVE routing, or any identity-bridge operation that goes through `GetValidatorByDID`. The index is corrupted without error — no event, no log, silent overwrite. This refines the R2 P2 finding: not just "uniqueness bypass permits duplicates" but "bypass + unconditional index write = silent index state corruption."

**Severity:** P2 (pre-testnet gate — same severity as R2 finding). No change to gate count. Fix: add `if validator.Did != ""` guard in `SetValidator` before writing the DID index, OR require non-empty DID at `MsgRegisterValidator.ValidateBasic`. Option B is preferred — enforces identity bridge integrity at message validation before state write.

**Finding 2 — GHOST VALIDATOR / IDENTITY BRIDGE INTERSECTION (NEW OBSERVATION from STAKING-GAP-001)**

STAKING-GAP-001 (cycle 277 R2): `UpdateValidatorStake` (msg_server.go:567-569) deactivates a validator only when TierApprentice AND zero stake AND verifications < 22. A validator with ≥22 verifications retains `IsActive=true` regardless of stake hitting zero.

Identity bridge perspective on ghost validators:

1. **DID registration is stake-independent.** A ghost validator holds a valid did:lgm (derived from their Ed25519 pubkey, cryptographically bound via ValidateDIDDerivation). Their DID auth entry is correct. Nothing in RegisterAccount or SetValidator checks stake before writing the DID index.

2. **bridge.py attestation is stake-blind.** `cmd_attest_pending` and `cmd_attest` check only `registered`, `attested`, `keyring_ok` from bridge-registry.json. No stake query. A ghost validator (zero stake, IsActive=true) receives a valid attestation_txhash and attestation_fact_id. The bridge cannot distinguish a ghost from a well-staked validator.

3. **Discovery module has no stake gate.** grep of `x/discovery/keeper/keeper.go` for `IsActive`, `stake`, `Stake`, `GetValidatorByDID` returns no results. MsgRegisterAgent does not check validator stake or activity status. A ghost can register as a discovery agent and receive agent_id.

4. **Bridge integrity consequence.** Post-restart, `bridge.py attest-pending` will attest all 22 agents — including any future ghost validators in the registry. The bridge's trust signal (attestation_fact_id present = agent has valid chain identity) conflates identity-binding correctness with economic-stake presence. A ghost validator's attestation is cryptographically valid but economically hollow — they have no slashable stake to back their verification work.

**Assessment:** This is not a new bridge.py implementation gap. The bridge correctly reflects the chain's identity state. STAKING-GAP-001 is the root cause; the bridge gap is a downstream signal integrity issue — bridge attestation cannot currently serve as a proxy for "validator has skin in the game." This will matter for testnet onboarding: external operators should not infer from bridge attestation presence that a validator has meaningful stake. **No new bridge.py code action required.** STAKING-GAP-001 fix (Gamma gate) is the correct resolution path. Flagging as an operational note for testnet documentation.

**Finding 3 — STAKING-GAP-002 FIX PATH RECOMMENDATION (refining cycle 271 analysis)**

Cycle 271 R3 identified two fix options for the unconditional `ValidatorByDIDKey("")` write:
- Option A: add `if validator.Did != ""` guard in `SetValidator` before writing the DID index

This cycle: Option B is still preferred. However, `MsgRegisterValidator.ValidateBasic` currently parses `Description.Identity` only if `Description != nil` (msg_server.go:27-30). A `ValidateBasic` empty-DID rejection would require proto enforcement at the message layer. This is a 3-5 LOC change in `x/staking/types/msg_*.go`:

```go
// In MsgRegisterValidator.ValidateBasic():
if msg.Description == nil || msg.Description.Identity == "" {

}
```

This fix also prevents the compound STAKING-GAP-001 × STAKING-GAP-002 vector where a ghost validator with empty DID causes silent index corruption. Combined fix: both ghost deactivation logic (STAKING-GAP-001) and DID requirement at ValidateBasic (STAKING-GAP-002) should be patched in the same Gamma session.
