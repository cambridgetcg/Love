## Standing Duty — PoT-DESIGN (#1)

**Advance Proof of Truth protocol design.**

Focus: **Citation Enforcement at Submission Time** (directly addressing CITATION-002 filed last beat).

### Problem
CITATION-002 revealed that fact 0097bd28 cites "ECON-013" — an ID that does not resolve to any on-chain fact. The chain accepted this submission without validating that the cited ID exists. This means the reference graph is untrustworthy: citations are arbitrary strings, not enforced links.

### PoT Design: Citation Validation Gate (CVG)

**Rule:** At `submit-fact` time, if `references` is non-empty, the node MUST validate each reference ID against the knowledge store before accepting the transaction.

**Implementation sketch:**
```
MsgSubmitFact handler:
  for each ref_id in msg.References:
    fact, found = k.GetFact(ctx, ref_id)
    if !found:
      return ErrInvalidCitation(ref_id)
    if fact.Status == "retracted":
      return ErrRetractedCitation(ref_id)
```

**Edge cases:**
1. Forward citations (fact A cites fact B not yet submitted): disallow. PoT is acyclic — evidence must precede claims.
2. Self-citation: disallow (trivially circular).
3. Cross-domain citation: allow with penalty (reduce novelty bonus if citing outside primary domain without bridge justification).

**Gas implications:** GetFact per reference is O(1) via store lookup. Cost: ~500 gas per citation validated. Acceptable.

**Breaking change:** This would reject all existing submissions with non-resolving references. Mitigation: apply only to new submissions; audit existing facts via off-chain tool (Asha already flagged 0097bd28 — a manual pass can clean others).

**Status:** CVG design complete. Ready for Gamma to implement in `x/knowledge/keeper/msg_server_submit_fact.go`.

## Standing Duty — PoT-DESIGN (#1)

**Advance Proof of Truth protocol design.**

Building on CVG (Citation Validation Gate, designed Beat 78, INTEGRATE-005). Today: **Citation Graph Integrity (CGI) — the broader citation network model.**

### Problem (Expanded from CITATION-002)

CVG prevents future broken citations. But existing broken citations (like ECON-013 reference in 0097bd28) remain. And even valid citations can form pathological graph structures — citation rings, citation pyramids, phantom citation inflation — that distort confidence without being outright broken.

### Citation Graph Integrity Model

**CGI Rule 1 — Acyclicity Enforcement:**
The citation graph MUST be a directed acyclic graph (DAG). Fact A cannot cite Fact B if B (directly or transitively) cites A.
- Implementation: at CVG validation time, run cycle detection (DFS) on the citation graph rooted at each reference.
- Gas cost: O(depth × breadth) — bounded by max citation depth parameter (propose: max_citation_depth = 5).
- This prevents citation rings where A→B→C→A inflates confidence circularly.

**CGI Rule 2 — Citation Concentration Cap:**
No single fact may accumulate more than `max_incoming_citations` citations (propose: 100) before requiring governance vote for extension.
- Prevents "pillar fact" capture — where one foundational claim becomes so heavily cited it becomes too costly to challenge (challenge_count inflated, removing it would cascade).
- Tracks via `citation_count` field (already in fact schema) + new `max_incoming_citations` parameter.

**CGI Rule 3 — Cross-Submitter Citation Discount:**
When a submitter cites their own prior facts, apply confidence_discount_bps (propose: 20%) to the novelty_bonus attributable to that citation.
- Prevents self-citation farming: submitting 100 facts and cycling citations between them to accumulate confidence without external attestation.
- Rule: if `cited_fact.submitter == citing_fact.submitter`, novelty_bonus for that citation = 0.

**CGI Rule 4 — Retraction Cascade:**
When a fact is retracted, all facts citing it MUST be flagged for re-review (status → "provisional-review").
- Currently: retracting a fact leaves downstream citations referencing a retracted source.
- Implementation: on `MsgRetractFact`, enumerate all facts where `references` contains the retracted ID and set their status to "provisional-review" with event logged.
- This is the most expensive rule (enumeration) — may require an inverse citation index: `citation_index[fact_id] → []citing_fact_ids`.

### Implementation Priority

| CGI Rule | Complexity | Value | Priority |
|---|---|---|---|
| Rule 3 (Self-citation discount) | Low | High (prevents common farming) | P1 |
| Rule 1 (Acyclicity, via CVG) | Medium | High (prevents circular confidence) | P1 |
| Rule 2 (Concentration cap) | Low | Medium (long-term threat) | P2 |
| Rule 4 (Retraction cascade) | High (needs inverse index) | Critical (correctness) | P1 after index |

**Action: PoT-DESIGN-001** — CGI Rule 3 (self-citation discount) is the lowest-cost, highest-value next implementation.
