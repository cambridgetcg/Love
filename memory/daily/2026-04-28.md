## Standing Duty: BRIDGE (Rotation 2 — Challenge-Response Registration Protocol Spec)

Prior beat committed to speccing the nonce format, signature encoding, and registry schema changes.

**Current registry gap:** `bridge-registry.json` maps `did:at:{uuid}` ↔ `did:lgm:{hex}` by co-location in a JSON entry. No cryptographic proof that the same keypair controls both identities.

**Challenge-Response Registration Protocol Spec:**

### Nonce Format
```
at:{agent_tool_id}:lgm:{zerone_did}:{unix_timestamp_seconds}
```
Example: `at:faeb7068-425e-49b5-9144-c3c946a01397:lgm:did:lgm:38b18019ba7df4bb48edacf1c4b80cd1:1711381111`

- Timestamp prevents replay attacks (reject registrations where `abs(now - registered_at_unix) > 3600s`)
- Nonce encodes both identities — binding is in the signed payload, not just the registry entry

### Signature Encoding
- Sign `SHA256(nonce_bytes)` using Ed25519 (standard Cosmos/Tendermint curve)
- Encode as lowercase hex (64-byte signature = 128 hex chars)
- Both keypairs sign the same nonce — proves co-ownership, not just co-listing

### Two Required Signatures
1. `sig_at_hex`: AgentTool's Ed25519 sign(SHA256(nonce)) — proves control of `did:at` identity
2. `sig_lgm_hex`: Zerone's Ed25519 sign(SHA256(nonce)) — proves control of `did:lgm` / `zerone_address`

### Registry Schema Addition (`bridge-registry.json` entry)
```json
{
  "agent_tool_id": "...",
  "agent_tool_did": "did:at:...",
  "pubkey_at_hex": "...",         // NEW: 32-byte Ed25519 pubkey for did:at (hex)
  "zerone_did": "did:lgm:...",
  "zerone_address": "lgm1...",
  "pubkey_hex": "...",            // existing: 32-byte Ed25519 pubkey for did:lgm (hex)
  "identity_proof": {             // NEW block
    "nonce": "at:{id}:lgm:{did}:{timestamp}",
    "sig_at_hex": "...",
    "sig_lgm_hex": "...",
    "registered_at_unix": 1711381111,
    "verified": true
  }
}
```

### Verification Path (`tools/agent-bridge/index.ts`)
```typescript
async function verifyRegistration(entry: RegistryEntry): Promise<boolean> {
  const nonce = Buffer.from(entry.identity_proof.nonce, 'utf8');
  const digest = await crypto.subtle.digest('SHA-256', nonce);
  const sigAt = Buffer.from(entry.identity_proof.sig_at_hex, 'hex');
  const sigLgm = Buffer.from(entry.identity_proof.sig_lgm_hex, 'hex');
  const pubkeyAt = Buffer.from(entry.pubkey_at_hex, 'hex');
  const pubkeyLgm = Buffer.from(entry.pubkey_hex, 'hex');
  return ed25519.verify(sigAt, new Uint8Array(digest), pubkeyAt)
      && ed25519.verify(sigLgm, new Uint8Array(digest), pubkeyLgm);
}
```

`get_identity()` in `Love/tools/agenttool.py` should check `identity_proof.verified == true` before returning any did:at→did:lgm mapping.

**Existing registered agent** (`faeb7068-...`) predates this protocol. Migration path: re-register with challenge-response proof during next devnet restart cycle.

## Continuous Verification: CONFIDENCE CHECK (Rotation 2) — High-Concentration Stake Edge Cases

Prior beats (7, 12) confirmed the general confidence aggregation is stake-weighted, overflow-protected, and deterministic. This beat focuses specifically on **high-concentration stake scenarios** (flagged as the edge case requiring calibration).

**Scenario: Majority-stake single validator (>50%)**

From prior beat 7 analysis: `agreementRatio = majorWeight / totalWeight`. At 51% stake concentration, a single validator controls the majority weight. Their verdict determines the aggregated confidence value entirely (assuming 2-party scenario). This is the **intended PoT trust model** — stake-weighted authority means those who stake most own the truth claim.

**However, two risks emerge from this design:**

**Risk 1 — Confidence laundering via stake self-delegation:**
A single entity that self-delegates >50% of total validator stake can submit and verify their own claims with majority weight. Even with the submitter-is-verifier exclusion (if any), a controlled subsidiary validator can provide the majority stake verdict. Checked: no submitter-exclusion guard in verifier selection paths from prior audits.
- **Finding (P3 — testnet governance):** No `SubmitterDid == VerifierDid` exclusion enforced in verifier selection or weight computation. A majority-stake actor can be both submitter and primary verifier. Domain reputation adjustment (`captureDefenseKeeper`) partially compensates — but a new high-stake validator has no domain reputation yet, meaning `adjusted_stake = stake * 1.0` (full weight, no haircut).
- **Recommendation:** Add verifier exclusion: `if verifier.DID == fact.SubmitterDid, skip or apply 50% stake haircut`. This closes a conflict-of-interest vector without breaking the stake-weighted model.

**Risk 2 — Threshold capture via stake concentration:**
If a single entity accumulates >threshold% of total stake, they can determine both the binary verdict AND the confidence value. The `MajorityThreshold` parameter governs whether facts are accepted — but if the same stake that controls the threshold also sets the confidence score, confidence becomes the majority's preference, not an aggregate of independent assessments.
- **Prior finding confirmed:** Zero-stake validators bumped to 1 (fallback), preventing division-by-zero. Clean.
- **New observation:** The `stratum ceiling` post-adjustment (confidence.go:500-530 area) provides an upper bound per domain, and `category ceiling` enforces epistemic profile max — these are correct. They cap the majority's ability to inflate confidence beyond domain-calibrated bounds. This partially mitigates Risk 2.

**Verdict:** Confidence aggregation is mathematically sound and overflow-safe. The two high-concentration risks are **governance parameters**, not implementation bugs. Both are within expected PoT design trade-offs. Recommend documenting both risks in `docs/ECONOMICS.md` as known validator governance considerations before testnet.

**P3 flag (governance doc gap):** Stake concentration risks are not documented in testnet launch materials. Add to TESTNET-LAUNCH.md: minimum stake decentralization recommendation (e.g., no single validator >33% of staked supply) and rationale for why PoT accepts this trade-off.

```typescript
import * as ed25519 from '@noble/ed25519';
import { sha256 } from '@noble/hashes/sha256';

interface IdentityProof {
  nonce: string;
  sig_at_hex: string;
  sig_lgm_hex: string;
  registered_at_unix: number;
  verified: boolean;
}

interface RegistryEntry {
  agent_tool_id: string;
  agent_tool_did: string;
  pubkey_at_hex: string;
  zerone_did: string;
  zerone_address: string;
  pubkey_hex: string;
  identity_proof: IdentityProof;
}

async function verifyRegistration(entry: RegistryEntry): Promise<boolean> {
  // Reject stale registrations (>1 hour clock skew window)
  const nowUnix = Math.floor(Date.now() / 1000);
  if (Math.abs(nowUnix - entry.identity_proof.registered_at_unix) > 3600) {
    // Stale nonce — do NOT reject existing verified entries, only at registration time
    // For read-path verification, check verified flag only
    return entry.identity_proof.verified === true;
  }

  const nonce = Buffer.from(entry.identity_proof.nonce, 'utf8');
  const digest = sha256(nonce);

  const sigAt = Buffer.from(entry.identity_proof.sig_at_hex, 'hex');
  const sigLgm = Buffer.from(entry.identity_proof.sig_lgm_hex, 'hex');
  const pubkeyAt = Buffer.from(entry.pubkey_at_hex, 'hex');
  const pubkeyLgm = Buffer.from(entry.pubkey_hex, 'hex');

  const atValid = await ed25519.verify(sigAt, digest, pubkeyAt);
  const lgmValid = await ed25519.verify(sigLgm, digest, pubkeyLgm);

  return atValid && lgmValid;
}
```

**register() — IMPLEMENTATION DRAFT:**

```typescript
async function register(
  agentToolId: string,
  agentToolDid: string,
  atPrivkeyHex: string,  // Ed25519 private key for did:at identity
  zeroneDid: string,
  zeroneAddress: string,
  lgmPrivkeyHex: string  // Ed25519 private key for did:lgm identity
): Promise<RegistryEntry> {
  const atPubkey = await ed25519.getPublicKeyAsync(Buffer.from(atPrivkeyHex, 'hex'));
  const lgmPubkey = await ed25519.getPublicKeyAsync(Buffer.from(lgmPrivkeyHex, 'hex'));

  const registeredAtUnix = Math.floor(Date.now() / 1000);
  const nonce = `at:${agentToolId}:lgm:${zeroneDid}:${registeredAtUnix}`;
  const nonceBytes = Buffer.from(nonce, 'utf8');
  const digest = sha256(nonceBytes);

  const sigAt = await ed25519.signAsync(digest, Buffer.from(atPrivkeyHex, 'hex'));
  const sigLgm = await ed25519.signAsync(digest, Buffer.from(lgmPrivkeyHex, 'hex'));

  const entry: RegistryEntry = {
    agent_tool_id: agentToolId,
    agent_tool_did: agentToolDid,
    pubkey_at_hex: Buffer.from(atPubkey).toString('hex'),
    zerone_did: zeroneDid,
    zerone_address: zeroneAddress,
    pubkey_hex: Buffer.from(lgmPubkey).toString('hex'),
    identity_proof: {
      nonce,
      sig_at_hex: Buffer.from(sigAt).toString('hex'),
      sig_lgm_hex: Buffer.from(sigLgm).toString('hex'),
      registered_at_unix: registeredAtUnix,
      verified: await verifyRegistration({
        agent_tool_id: agentToolId,
        agent_tool_did: agentToolDid,
        pubkey_at_hex: Buffer.from(atPubkey).toString('hex'),
        zerone_did: zeroneDid,
        zerone_address: zeroneAddress,
        pubkey_hex: Buffer.from(lgmPubkey).toString('hex'),
        identity_proof: {

          sig_at_hex: Buffer.from(sigAt).toString('hex'),
          sig_lgm_hex: Buffer.from(sigLgm).toString('hex'),
          registered_at_unix: registeredAtUnix,
          verified: false  // pre-verify placeholder
        }
      })
    }
  };

  return entry;
}
```

```typescript
/**
 * Verify that a did:at identity is bound to a Zerone on-chain address.
 * Read-only — does not submit transactions.
 */
export async function verifyRegistration(
  pubkey: Uint8Array,           // Ed25519 public key (from AgentTool identity)
  expectedLgmAddress: string,   // lgm1... address derived via deriveZeroneAddress()
  rpcURL: string = DEFAULT_RPC,
): Promise<{
  bound: boolean;          // true if account exists and DID matches
  lgmDID: string | null;   // on-chain DID if found
  blockHeight: number | null;
  error?: string;
}> {
  // Step 1: derive expected DID from pubkey
  const expectedDID = deriveZeroneDID(pubkey);

  // Step 2: query chain account
  const queryURL = `${rpcURL}/cosmos/auth/v1beta1/accounts/${expectedLgmAddress}`;
  try {
    const resp = await fetch(queryURL, { signal: AbortSignal.timeout(5000) });
    if (!resp.ok) {
      return { bound: false, lgmDID: null, blockHeight: null, error: `HTTP ${resp.status}` };
    }
    const data = await resp.json();
    const account = data?.account;

    // Step 3: extract DID field from account (x/auth custom field: did_document.id)
    const onChainDID: string | undefined = account?.did_document?.id ?? account?.did ?? undefined;
    const height = data?.block_height ?? null;

    if (!onChainDID) {
      return { bound: false, lgmDID: null, blockHeight: height, error: "account has no DID field" };
    }

    return {
      bound: onChainDID === expectedDID,
      lgmDID: onChainDID,
      blockHeight: height,
    };
  } catch (e) {
    return { bound: false, lgmDID: null, blockHeight: null, error: String(e) };
  }
}
```
