**Target:** `x/knowledge/keeper/confidence.go` — `AggregateVerificationResult` and `calculateRewardsAndSlashes`.

**Finding 1 — Quorum by COUNT, not STAKE (flag #25 NEW):**

`confidence.go:118-124` computes participationRatio as:
```go
participationRatio = (uint64(len(round.Reveals)) * 1_000_000) / uint64(len(round.SelectedValidators))
```

This is a **validator count** ratio, not a stake-weight ratio. The param description says `QuorumThreshold: 660000 // 66% participation required` — implying stake-weighted participation. But the actual check is: how many of the selected validators revealed (by head count).

**Impact:** 66 Tier-0 micro-validators (each with 0.01% stake, total 0.66% stake) can satisfy quorum while 34 whale validators (holding 99.34% stake) abstain. The resulting confidence score would be stake-weighted over those 66 micro-validators — producing a high-confidence result backed by <1% of total network stake. This is a systematic underspecification of the quorum definition.

**Classification:** P2 semantic gap — the intent (meaningful participation threshold) diverges from the implementation (head-count minimum). Fix: compute participationRatio as `sum(stake for reveals) / sum(stake for selectedValidators)`. Gamma Sprint A (pre-testnet gate — affects consensus integrity).

The 55% contested boundary is a magic constant, not a governance param. `AcceptanceThreshold` (77%) and `QuorumThreshold` (66%) are both configurable via params. The contested threshold is not. A governance proposal cannot adjust where the accepted/contested boundary falls without a code upgrade.

**Classification:** P3 parameter hygiene. Add `ContestedThreshold uint64` to `x/knowledge/types/Params`. Default 550000. Gamma Sprint C (low urgency — not pre-testnet blocking, but needed before mainnet governance).
