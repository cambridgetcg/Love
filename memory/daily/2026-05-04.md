**Utility signature** (place in `x/knowledge/keeper/utils.go`):

```go
// StakeWeightedCardinality computes the fraction of totalStake held by the
// deduplicated set of addresses, expressed in [0, 1_000_000].
// Primitive for stake-weighted quorum (#25) and domain diversity (#27).
func StakeWeightedCardinality(
    addresses []string,
    stakeGetter func(addr string) uint64,
    totalStake uint64,
) uint64 {
    if totalStake == 0 {
        return 0
    }
    seen := make(map[string]struct{}, len(addresses))
    var weightedSum uint64
    for _, addr := range addresses {
        if _, dup := seen[addr]; dup {
            continue
        }
        seen[addr] = struct{}{}
        weightedSum += stakeGetter(addr)
    }
    return safeMulDiv(weightedSum, 1_000_000, totalStake)
}
```

### Standing Duty: ECONOMY (Rotation 3) — ZRN Tokenomics Design Advance

**Focus: Addressing the burn accounting gap and designing a complete economic health API.**

The missing burn/lock meter data means no external tool can accurately compute circulating supply:

```
Circulating = TotalMinted - TotalLocked - TotalBurned
```

With `TotalBurned = 0` (meter bug) and `TotalLocked = 0` (meter bug), the computed circulating supply is permanently overstated. Any ZRN economic dashboard, exchange listing, or external audit will receive a false figure. This is not theoretical — burns are happening now via billing protocol revenue.

**Design proposal: Economic Integrity Invariant (EII)**

Add a keeper-level assertion (can run in EndBlock or via query) that verifies:

```
TotalMinted >= TotalRouted   // can't route more than minted
TotalMinted >= TotalBurned   // can't burn more than minted
TotalMinted - TotalLocked - TotalBurned <= BankSupply("ulgm")  // circulating ≤ bank balance
```

This is O(1) — all values come from the meter. Failure = economic invariant violation, escalate immediately.
