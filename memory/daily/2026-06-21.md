**Finding 1 — P3-G REVEAL-EXPIRY QUORUM BYPASS (phases.go:225)**
`handleExpiredRound` for a round still in "reveal" phase (phases.go:224-234) checks only `len(round.Reveals) == 0` before calling `performAggregation`. It does NOT check `len(round.Reveals) < params.MinVerifiers`. By contrast, `transitionToAggregation` (phases.go:178) correctly enforces `uint32(len(round.Reveals)) < params.MinVerifiers → insufficient`. The discrepancy is reachable when `AggregationPhaseDuration = 0`: at that setting, `GetRoundPhase` returns "expired" directly from "reveal" without ever returning "aggregation", so `transitionToAggregation` is never called and `handleExpiredRound` fires. A round with 1 or 2 reveals (below MinVerifiers) would then proceed to `performAggregation` and produce a verdict with insufficient participants. Impact: potential under-quorum verdicts if AggregationPhaseDuration is zero or if a round's aggregation window is extremely short. Fix: add `uint32(len(round.Reveals)) < params.MinVerifiers` check in `handleExpiredRound` "reveal" branch before calling `performAggregation`. P3 — non-blocking if production params ensure AggregationPhaseDuration > 0; verify default params before testnet.

**Finding 2 — P3-H COUNTER-FACT STAKE USES HARDCODED SLASH BPS (rounds.go:1054)**
`createRejectionCounterFact` derives the auto-counter-fact's nominal stake using `big.NewInt(220_000)` (22%) hardcoded, rather than `params.InvalidClaimSlashBps`. If governance adjusts `InvalidClaimSlashBps`, the auto-counter-fact stake will not track the actual slash — it will be systematically over- or under-weighted in the bidirectional confidence calculation. Fix: call `k.GetParams(ctx)` inside `createRejectionCounterFact` and use `params.InvalidClaimSlashBps`. P3 — pre-testnet correction for governance consistency.
