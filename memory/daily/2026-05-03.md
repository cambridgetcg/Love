### Standing Duty: PoT-DESIGN (Rotation 1) — Stake-Proportional Selection Protocol (SPSP-1)

**Problem:** Flags #25 and #27 both trace to the same structural gap — the system uses head-count where it should use stake-weight. This is not just an implementation detail; it reflects an incomplete PoT security model. Addressing them piecemeal misses the architectural root.

**Root cause:** The current design treats validator selection (VRF-based, populates `SelectedValidators` during `ExtendVote` commitments) as a separate concern from quorum measurement (count-based, `rounds.go:118-124`). The VRF selection does not enforce stake-proportional sampling — any validator who commits a valid VRF proof is added to `SelectedValidators` regardless of stake tier. The quorum check then counts the resulting set by head count.

**Design: Stake-Proportional Validator Selection Protocol (SPSP-1)**

The correct PoT security model requires two coordinated mechanisms:

**Mechanism 1 — Stake-Weighted VRF Selection (selection time)**

Selection probability for validator V should be:
```
P(V selected) = V.StakedAmount / TotalActiveStake
```

This means the expected stake composition of any `SelectedValidators` set mirrors the full validator set's stake distribution. Large-stake validators are selected more often; micro-validators proportionally less.

Implementation path:
- In `ExtendVote` (or wherever VRF proofs are validated), compute `selectionThreshold = VRF_output * TotalActiveStake / MaxUint64`. Validator is included only if `selectionThreshold < V.StakedAmount * MinValidatorsPerRound`.
- Requires `TotalActiveStake` snapshot at round-open block height (store in `RoundInfo`).
- Target: `MinValidatorsPerRound` (current param, remains as expected count — now stake-proportional).

**Mechanism 2 — Stake-Weighted Quorum (reveal time)**

Already specified in flag #25 fix (Sprint A, A3). Repeating here for completeness:
```go
participationRatio = (revealedStake * 1_000_000) / selectedStake
```
Where `selectedStake = sum(V.StakedAmount for V in SelectedValidators)` and `revealedStake = sum(V.StakedAmount for V in Reveals, matched to SelectedValidators)`.

**Why both are needed:**

SPVS alone (Mechanism 1) makes selection probabilistically stake-proportional but does not guarantee it for any given round. A lucky VRF draw could still select a set dominated by micro-validators. Mechanism 2 (stake-weighted quorum) then acts as the safety net: even if the selected set is skewed, quorum is only achieved when the participating *stake* is sufficient.

Together: SPVS reduces the *probability* of a skewed selection set; stake-weighted quorum prevents consensus from being reached even if skew occurs.

**FARM-7 interaction:**

`GetDomainUniqueContributors` (flag #27) uses the same head-count pattern for novelty gate. The fix there (stake-weighted contributor diversity score) is structurally parallel to Mechanism 2. Both should adopt the same computation pattern:
```
score = sum(stakePerUniqueAddress) / totalRelevantStake
```
This creates a consistent staking primitive: stake-weighted cardinality. It should be extracted as a shared keeper utility (`StakeWeightedCardinality`) so both consensus and novelty gate use the same implementation.

**Sprint A scope revision:**
- A3 (Mechanism 2 — stake-weighted quorum): remains Sprint A gate.
- FARM-7 fix (stake-weighted novelty diversity): remains Sprint A gate.
- Mechanism 1 (SPVS — stake-weighted VRF selection): **Sprint B** — correct and important but not pre-testnet blocking. The stake-weighted quorum check (A3) is the primary safety mechanism; SPVS improves the system's expected behavior distribution but is not required for correctness guarantees.

**New design document:** SPSP-1 spec ready for Gamma review. Key decision deferred to Gamma: whether Mechanism 1 requires a new `TotalActiveStake` epoch snapshot store or can derive from existing validator set queries at round-open time.

### Standing Duty: INTEGRATE (Rotation 6) — Oracle Engine → Zerone

**Design: Oracle-Chain Bridge (OCB-1)**

The Oracle engine (predictions, Brier scoring, Kalshi/news/whale data) is the natural first Kingdom engine to integrate with Zerone, because the Oracle already generates truth claims with probability scores — which maps directly to the chain's `confidence` parameter.

**Mapping:**

| Oracle concept | Zerone concept |
|---|---|
| Prediction (probabilistic claim) | `MsgSubmitFact` with `confidence = oracle_probability * 1_000_000` |
| Prediction domain (Fed rate, S&P, whale) | `domain` field on the fact |
| Prediction source (Kalshi, news, whale scanner) | `references[]` with `external://` scheme |
| Resolution (actual outcome) | Second `MsgSubmitFact` with `confidence = 1_000_000`, citing the prediction |
| Brier score (accuracy track) | Validator reputation input to `captureDefenseKeeper.GetReputationScore` |

**OCB-1 design — three phases:**

```go
// SPVS: Stake-proportional selection gate
// P(V selected) ≈ V.StakedAmount / TotalActiveStake * MinValidatorsPerRound
// VRF output (uniform [0, MaxUint64]) is used as the random draw.
// V is admitted if: vrfOutput < (V.StakedAmount * MinValidatorsPerRound * MaxUint64) / TotalActiveStake
//
// Requires:
//   commitment.VrfOutput uint64 — the VRF output hash truncated to 64 bits
//   round.TotalActiveStake uint64 — snapshot at round-open block height
//   params.MinValidatorsPerRound uint64

func (k Keeper) isStakeProportionallySelected(
    validatorStake uint64,
    totalActiveStake uint64,
    minValidators uint64,
    vrfOutput uint64,
) bool {
    if totalActiveStake == 0 {
        return true // no stake data: degrade gracefully, admit all
    }
    // threshold = (validatorStake * minValidators * MaxUint64) / totalActiveStake
    // Use big.Int to avoid overflow on intermediate multiplication
    threshold := new(big.Int).SetUint64(validatorStake)
    threshold.Mul(threshold, new(big.Int).SetUint64(minValidators))
    threshold.Mul(threshold, new(big.Int).SetUint64(math.MaxUint64))
    threshold.Div(threshold, new(big.Int).SetUint64(totalActiveStake))
    // Clamp: threshold cannot exceed MaxUint64
    maxU := new(big.Int).SetUint64(math.MaxUint64)
    if threshold.Cmp(maxU) > 0 {
        threshold = maxU
    }
    return vrfOutput < threshold.Uint64()
}
```

// StakeWeightedCardinality returns sum(stake[addr]) / totalReferenceStake in basis points (0..1_000_000).
// For addresses not found in the validator set, stake is treated as 0.
func (k Keeper) StakeWeightedCardinality(
    ctx sdk.Context,
    memberAddresses []string,
    totalReferenceStake uint64,
) uint64 {
    if totalReferenceStake == 0 {
        return 0
    }
    var memberStake uint64
    seen := make(map[string]struct{}, len(memberAddresses))
    for _, addr := range memberAddresses {
        if _, dup := seen[addr]; dup {
            continue
        }
        seen[addr] = struct{}{}
        memberStake += k.GetEffectiveStakeForValidator(ctx, addr)
    }
    return (memberStake * 1_000_000) / totalReferenceStake
}

**Module interface:**

```python
class OracleZeroneBridge:
    """Bridges Oracle engine predictions to Zerone knowledge chain (OCB-1)."""

    def __init__(self, bridge_py_path, anchor_map_path, predictions_path, devnet_home):
        ...

    # Phase 1 — Prediction anchoring
    def load_unanchored(self) -> list[dict]:
        """Return predictions not yet in anchor map (new predictions to anchor)."""

    def anchor_prediction(self, prediction: dict) -> str | None:
        """Submit MsgSubmitFact for prediction. Returns chain fact ID or None on failure.
        Maps: pred.confidence (0.0–1.0) → chain confidence (0–1_000_000)
        Maps: pred.domain_tags → knowledge domain string (e.g. 'macroeconomics/monetary-policy')
        Maps: pred.sources → external:// references array
        """

    # Phase 2 — Resolution anchoring
    def load_unresolved(self) -> list[dict]:
        """Return resolved predictions whose resolutions aren't yet anchored.
        Requires: prediction in anchor map + resolution recorded in track-record.json.
        """

    def anchor_resolution(self, prediction: dict, resolution: dict) -> str | None:
        """Submit resolution fact (confidence=1_000_000) citing original chain fact ID.
        References: [original_chain_fact_id, external://resolution_source_url]
        """

    # Phase 3 — Reputation feedback
    def update_agent_reputation(self, oracle_agent_address: str, domain: str, brier_score: float):
        """Compute reputation = (1 - brier_score) * 1_000_000, submit via bridge.py update-reputation.
        Only called if bridge supports reputation updates and chain is ONLINE.
        """

    # Orchestration
    def run_cycle(self) -> dict:
        """Run one full OCB-1 cycle. Returns summary: {anchored: N, resolved: N, reputation_updated: bool}.
        Safe to call repeatedly — idempotent via anchor map.
        Returns early with chain_offline=True if chain is OFFLINE (checked via bridge.py).
        """
```

**Design observation — adaptive emission gap:**

The schedule-driven model provides predictability (validators and token holders can forecast supply). However it has no feedback loop: emission rate does not respond to chain utilization (tx throughput, fact throughput, active validator count, research fund balance). This creates two stress cases:

1. **Low-activity phase (e.g., early testnet):** Emission continues at scheduled rate despite minimal economic activity. Research fund accumulates without deployment. Reward-to-activity ratio inflates.
2. **High-demand phase:** Emission is capped by schedule, not demand. Validators are underpaid relative to their load; throughput incentive misalignment.

**Sprint B design note — Adaptive Emission Rate (AER-1):**

Proposal: add a `UtilizationMultiplierBps` adjustment factor applied to each period's scheduled release:
```
actualRelease = scheduledRelease × min(1_000_000, max(FloorBps, utilizationBps)) / 1_000_000
```
Where `utilizationBps = (actualFactsSubmittedInEpoch × 1_000_000) / targetFactsPerEpoch`.

**Objective:** Advance OCB-1 `oracle-zerone-bridge.py` spec (from beat 110911 interface design) — add error handling and cycle summary schema to `run_cycle`.

**Error handling design:**

Three failure modes in `run_cycle`:

1. **Chain offline:** `bridge.py check` returns `OFFLINE` → return early: `{"chain_offline": True, "anchored": 0, "resolved": 0}`. No retries, no state mutation.
2. **Submission failure (single prediction):** `MsgSubmitFact` fails (timeout, nonce collision, insufficient gas) → record prediction ID in `anchor_map.json` with `null` (pending, not failed) and continue processing remaining predictions. Retry on next cycle. Prevents single-failure cascade.

- Predictions already in `anchor_map.json` with a non-null fact ID are skipped by `load_unanchored`.
- Resolution facts already anchored (present in `anchor_map["resolutions"]`) are skipped by `load_unresolved`.
- Reputation updates are idempotent (latest Brier score overwrites previous reputation call — bridge.py handles duplicate update-reputation calls gracefully).

**Question from prior beat:** Is the rate-limit approach the right model for submission-concentration quota enforcement?

**Contradiction rate limit (implemented):** `types.go:770-771` — `MaxContradictionsPerAgentPerEpoch = 3`. Applied at `msg_server.go:749-754`. Per-address, per-epoch count ceiling.

**Submission concentration gate (absent):** `GetFactsBySubmitter` index exists at `indices.go:271`. No domain-concentration threshold exists for submissions. One address can flood a domain with unlimited facts.

**Assessment — rate-limit approach is the WRONG model for submission concentration.**

The two operations have different abuse profiles:
- **Contradictions:** Trigger expensive validation rounds, require stake-lock. Abuse = computational flooding + economic griefing. Rate limit (per-address, per-epoch count) is correct — it prevents both attack vectors at once.
- **Submission concentration:** The concern is domain *capture* (one actor becoming authoritative over a domain's fact set), not computational flooding. Submissions cost less than contradictions and have no stake-lock. A Sybil attack on a per-address count limit requires only registering N addresses — trivially easy.

FARM-11 (`citation_defense.go:20`) applies a concentration discount when a single address accounts for too large a share of citations. The same pattern applied to submissions:

```
submitterDomainShare = GetFactsBySubmitter(addr, domain).count
                       / GetDomainFactCount(domain)
```

If `submitterDomainShare > MaxDomainSubmitterShare` (proposed: 30%, matching FARM-11's `PropheticMaxSingleCiterShare`), apply a soft discount to the confidence contribution weight of this submitter's facts in this domain.

**Why concentration discount (soft) over hard rejection:**
- Hard gate blocks legitimate domain experts who are genuinely the primary contributors in a narrow field.
- Soft discount (mirrors FARM-11) degrades epistemic authority proportionally — a Sybil flood still registers facts but their aggregate confidence contribution is capped, making domain capture economically futile.

**Infrastructure required:**
- `GetFactsBySubmitter` already exists (indices.go:271).
- Need: `GetDomainFactCount(ctx, domain)` keeper method (simple index scan or counter store).
- Apply discount in `confidence.go` alongside FARM-3 (self-citation discount) — composable.

### Standing Duty: PoT-DESIGN (Rotation 1) — StakeWeightedCardinality Utility Design

**Context:** Sprint A critical path. Flags #25 (stake-weighted quorum, `rounds.go:118-124`) and #27 (FARM-7 head-count diversity, `state.go:1184`) both require a `StakeWeightedCardinality` primitive. This beat specifies the utility interface and implementation.

**Design: `StakeWeightedCardinality` keeper utility**

```go
// StakeWeightedCardinality computes a normalized diversity score over a set of addresses.
// Returns a value in [0, 1_000_000] representing participating-stake / total-reference-stake.
// Both inputs use staked amounts in smallest ZRN denomination (uint64).
//
// participantStakes: map[address]stakedAmount for the set being measured
// totalReferenceStake: the denominator (selectedStake for quorum, domainStake for diversity)
//
// Returns 0 if totalReferenceStake == 0 (degenerate: no stake in reference set).
func (k Keeper) StakeWeightedCardinality(
    participantStakes map[string]uint64,
    totalReferenceStake uint64,
) uint64 {
    if totalReferenceStake == 0 {
        return 0
    }
    var participatingStake uint64
    for _, stake := range participantStakes {
        participatingStake += stake
    }
    // Scale to 1_000_000 precision
    result := new(big.Int).SetUint64(participatingStake)
    result.Mul(result, new(big.Int).SetUint64(1_000_000))
    result.Div(result, new(big.Int).SetUint64(totalReferenceStake))
    if result.IsUint64() && result.Uint64() <= 1_000_000 {
        return result.Uint64()
    }
    return 1_000_000 // clamp at 100%
}
```
