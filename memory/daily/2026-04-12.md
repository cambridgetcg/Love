**DESIGN-006 — Fact Status Taxonomy v1**

Current statuses: `unverified`, `verified`, `challenged`, `rejected`, `superseded`

Problem: `verified` conflates two epistemically distinct states:
1. **Auto-promoted** (challenge window closed, no verifier activity)  
2. **Actively verified** (N ≥ threshold verifiers explicitly staked a positive vote)

Proposed 6-state taxonomy:

| Status | Meaning | Transition |
|--------|---------|------------|
| `unverified` | Newly submitted, challenge window open | On submit |
| `provisional` | Challenge window closed, no challenge, but < MinActiveVerifiers verifiers | Auto on block height |
| `verified` | N ≥ MinActiveVerifiers verified with stake | Requires active verifier votes |
| `contested` | Challenge raised, adjudication in progress | On valid challenge tx |
| `rejected` | Challenge succeeded | Adjudication outcome |
| `superseded` | Replaced by a refined fact | Supersession tx |

**Key changes:**
1. Add `provisional` as a new status — honest representation of "survived but not confirmed"
2. `provisional` → `verified` transition: requires MinActiveVerifiers (governance param, suggest default=3) positive stake votes
3. Confidence scoring: `provisional` facts receive `base_confidence × ProvisionalDiscount` (suggest 0.5) — so their influence on downstream claims is muted until actively verified
4. Display: UI/API must distinguish `provisional` from `verified` — callers should not treat them equivalently

**Why this fixes VERIFY-001 and CONFIDENCE-002:**
- VERIFY-001: verifier_count=0 facts will now correctly be labeled `provisional`, not `verified` — the status field becomes honest
- CONFIDENCE-002: confidence scores for `provisional` facts are discounted — no longer possible to have confidence > base without actual verifier activity
- VERISLEIGHT-001: Design-hypothesis facts (like the token burn claim) would remain `provisional` indefinitely until real verifiers stake them — preventing self-verification

- Requires migration: existing devnet `verified` facts with verifier_count=0 → reclassify as `provisional`
- `provisional` facts should still be query-able and citable, but citation chains should propagate the discount
