func (k msgServer) validateReferences(ctx sdk.Context, refs []string) error {
    for _, ref := range refs {
        if !isValidCitationAnchor(ref) {
            return fmt.Errorf("invalid citation anchor %q", ref)
        }
        if !strings.HasPrefix(ref, "external://") {
            if _, found := k.GetFact(ctx, ref); !found {
                return fmt.Errorf("cited fact %q does not exist", ref)
            }
        }

## 6. Standing Duty: INTEGRATE (slot 6, cycle 13)

**Focus: Seigei → Zerone integration design (first full engine mapping)**

Seigei is the Kingdom's audio/social platform (beta-live at seigei.ai-love.cc). It generates user-verified social data: voice interactions, content consensus, and community engagement signals. This session designs how Seigei plugs into Zerone as a knowledge source.

**Integration architecture:**

```
Seigei (social layer)
    │
    ├── content_verification events
    │       → MsgSubmitFact(category: "social_consensus")
    │       → claim_text: "<content_id> received consensus approval from <N> verified users"
    │
    ├── community_challenge events
    │       → MsgSubmitChallenge (when community disputes a claim)
    │       → links to original content_verification fact
    │
    └── user_reputation signals
            → Seigei verified users → derived as verifier weight modifier
            → NOT submitted as facts; used to weight MsgCommitVerification
```

**Key design decisions:**

1. **Seigei users as Zerone verifiers (not submitters).** Social consensus on Seigei should influence *verification weight* on Zerone, not create new independent fact submissions. A Seigei user who has ≥N verified interactions gets a `reputation_bonus_bps` modifier in `confidence.go` — they are recognized as a trusted verifier. This avoids flooding the fact store with social data; instead, social trust amplifies oracle/knowledge verifier weight.

2. **Content consensus as a fact category.** High-confidence Seigei events (content approved by ≥threshold users) generate `MsgSubmitFact` with category `social_consensus`. These facts are staked by the Seigei bridge account (funded with ZRN).

3. **Bridge account:** `seigei-bridge` account on Zerone, funded from foundation account (100K LGM genesis), refilled via Seigei revenue. Each fact submission costs gas + stake. With ~100K LGM bootstrap, bridge can sustain ~1,000 fact submissions at 100 LGM/fact stake before needing reload.

4. **Counter-claim hook.** If Seigei content is later reported (community appeal), `MsgSubmitChallenge` fires automatically against the original `social_consensus` fact. This mirrors the oracle bridge counter-claim recommendation from beat 25.

**Blocker for this integration:** Same as oracle bridge — Zerone devnet is offline. Bridge can be coded now; live testing awaits chain restart.
