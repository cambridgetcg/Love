## 6. Standing Duty: INTEGRATE (slot 6, cycle 20)

**Focus: Fact Consumption Tracking — how Kingdom engines report which Zerone facts they used**

The billing module's `calculateKnowledgePoolDistribution()` (`billing/keeper/distribution.go:128`) requires `factIds []string` — the set of facts the service consumed. It then routes 30% of the service payment to those fact submitters, weighted by `confidence × log₂(citations+1)`. This is artiance by design: verified, cited knowledge earns from usage.

**The missing link: who provides factIds?**

For the billing revenue loop to close, each Kingdom engine must track which Zerone facts informed its outputs. Currently no engine does this systematically. This beat designs the protocol.

**Fact Consumption Tracking (FCT) protocol:**

```
Engine produces an output (Oracle prediction, Seigei content recommendation, AI service response)
    │
    ├── Engine queries Zerone for relevant facts (existing: via GetFact, query knowledge facts)
    │       └── logs returned fact IDs to a local consumption ledger
    │
    ├── When billing event fires (user pays for output):
    │       └── Engine reads consumption ledger → provides factIds to billing module
    │
    └── Billing routes 30% of payment → fact submitters via calculateKnowledgePoolDistribution()
```

**Per-engine FCT integration design:**

1. **Oracle** — when a prediction is generated, query Zerone for facts in the relevant domain (e.g., "macroeconomic" for FOMC predictions). Log matching fact IDs to `data/oracle-fact-consumption.jsonl`. On prediction resolution billing event, pass these IDs to billing. Effort: ~50 lines in `oracle-run.py`.

2. **Seigei** — when content recommendations are generated, tag which knowledge facts influenced the recommendation (confidence threshold ≥ 0.8). Log to `seigei-fact-consumption.json`. On user subscription billing event, aggregate fact IDs from the session. Effort: bridge already exists (`seigei-zerone-bridge.sh`); add FCT hook.

3. **AgentTool / AI Services** — each agent session that queries Zerone facts (via KTA bridge) auto-logs fact IDs to session context. On session billing event, pass aggregated fact IDs. This is the cleanest engine: agent sessions are already instrumented.

4. **Cambridge TCG** — the TCG service doesn't consume knowledge facts directly. It's a product (card marketplace), not an AI knowledge service. FCT does not apply. TCG contributes to Kingdom revenue, not to Zerone's knowledge economy.

**FCT implementation priority:**

AgentTool → Zerone FCT is highest leverage: every agent session that queries verified knowledge would generate citation revenue for fact submitters, creating a self-reinforcing incentive loop. Build this first.

**Concrete next action:** Add `--log-facts <file>` flag to KTA bridge calls so agent heartbeat queries accumulate fact IDs. When a billing event fires (via AgentTool session completion), flush the log as the `factIds` argument to the billing module.

**This adds one item to the integration roadmap:** FCT protocol before any engine generates billed outputs. Without it, billing's 30% knowledge pool distribution cannot function.
