## Standing Duty: PoT-DESIGN — Confidence Formula Specification

Today's confidence check confirmed the formula is not gating on verifier_count. Drafting the required fix:

**Current behaviour (broken):**
- Confidence initialized at submission (e.g., 700k–770k)
- No reduction or hold for zero verifiers
- `status=verified` set without verifier action
- `is_provisional=false` without verifier action

**Required state machine:**

```
SUBMITTED → PROVISIONAL (no verifiers, confidence = 0 or null)
PROVISIONAL → VERIFYING (verifier_count >= 1, confidence = f(stake))
VERIFYING → VERIFIED (verifier_count >= threshold, confidence = f(stake_weights))
VERIFIED → RETRACTED (counter-evidence, confidence drops below floor)
```

**Confidence formula:**
```
confidence = sum(verifier_stake[i] * weight[i]) / total_eligible_stake
           where weight[i] = 1 / (1 + distance_from_domain_median)
```
- Must return 0 (or null) when verifier_count = 0
- Must gate status transitions on count, not just a calculation result
- is_provisional must mirror: true ↔ verifier_count < 1

**Submission guard (claim_text):**
- Minimum 20 non-whitespace characters
- Must contain at least one verb (simple heuristic)
- Reject "Knowledge claim at block N in domain X" pattern

These 4 fixes eliminate the most severe pre-testnet integrity gaps confirmed across 3 days of beats.
