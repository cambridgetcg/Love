## Standing Duty: PoT-DESIGN (Rotation 1)

**Design advance: FARM-5 Enforcement Mechanism**

Current gap: validators can abstain indefinitely with zero risk and no penalty. Proposed enforcement:

**AbstainRateRecord** (new state entry, alongside VerifierConformityRecord):
```
AbstainRateRecord {
  ValidatorAddr  string
  TotalRounds    uint64
  AbstainVotes   uint64
}
```

**Enforcement rule (add to confidence.go reward loop):**
- Track abstain votes per validator in `UpdateVerifierConformity` (extend existing FARM-1 tracking path)
- Gate: if AbstainVotes / TotalRounds > 0.30 AND TotalRounds >= 10: apply escalating eligibility penalty
  - 30-50% abstain rate: reduce reward by 15%
  - >50% abstain rate: exclude from round selection for next 5 rounds (participation gate)
  - >80% abstain rate: flag for stake-weighted ejection (governance review)

**Why 30% threshold:** Occasional abstention is legitimate (insufficient expertise, declared conflict). Chronic abstention above 30% over 10+ rounds signals free-riding.

**Implementation path:** Extend `UpdateVerifierConformity` → add AbstainRate field → add `GetAbstainPenaltyBPS` mirroring existing `GetConformityPenaltyBPS` pattern. One new state key, one new penalty computation. Pre-testnet gate.

**Flagged for Gamma:** Design ready. FARM-5 is the last behavioral-detection gap confirmed absent from production. Recommend implementing alongside `citation.go:103` fix.

## Standing Duty: PoT-DESIGN (Rotation 1) — FARM-5 Architecture Correction

**Prior design error corrected:**

Beat asha-beat-20260429-034816 proposed implementing FARM-5 in `evaluation/abstain.go` following the `calibration.go` pattern. This was an **architectural misread**.

`calibration.go` is called from `EvaluateClaim` in `evaluation/engine.go` — it adjusts **claim confidence** based on submitter track record. FARM-5 is not about claim confidence; it is about **validator reward adjustment** based on abstention pattern over rounds.

The correct implementation target is `keeper/confidence.go`, specifically the reward distribution loop near line 310 where:
- `reveal.Verdict != "abstain"` is already checked to gate slashing
- Validator rewards are computed and distributed

**Corrected FARM-5 specification:**

**New state:** `ValidatorAbstainRecord` in `keeper/` state store
```
ValidatorAbstainRecord {
    ValidatorAddr  string
    TotalRounds    uint64
    AbstainRounds  uint64
}
```
Key prefix: `ValidatorAbstainRecord/` (alongside `VerifierConformityRecord/` in `rounds.go`)

**New functions (keeper/confidence.go or new keeper/abstain_tracking.go):**
```go
// UpdateValidatorAbstainRecord increments TotalRounds for all validators
// in a round, and AbstainRounds for those whose reveal.Verdict == "abstain".
// Called from the same loop that calls UpdateVerifierConformity.
func (k Keeper) UpdateValidatorAbstainRecord(ctx sdk.Context, validator string, didAbstain bool)

// GetAbstainPenaltyBPS returns a reward reduction in BPS (0-1_000_000)
// based on the validator's historical abstain rate.
// Rate thresholds: >30% && >=10 rounds: 150_000 BPS (15% penalty)
//                 >50% && >=10 rounds: 300_000 BPS (30% penalty)
//                 >80% && >=10 rounds: eligibility flag (governance review)
func (k Keeper) GetAbstainPenaltyBPS(ctx sdk.Context, validator string, ep types.ExtendedParams) uint64
```

**Integration point:** In `confidence.go` reward distribution loop (near line 310), after the existing conformity penalty check:
```go
// FARM-5: Abstain rate penalty
abstainPenaltyBPS := k.GetAbstainPenaltyBPS(ctx, reveal.Validator, ep)
if abstainPenaltyBPS > 0 && reveal.Verdict != "abstain" {
    reward = safeMulDiv(reward, 1_000_000 - abstainPenaltyBPS, 1_000_000)
}
k.UpdateValidatorAbstainRecord(ctx, reveal.Validator, reveal.Verdict == "abstain")
```

**Why penalty applies only to non-abstain reveals:** A chronic abstainer who finally reveals should earn reduced reward (they've been free-riding); their reward is discounted by their history. The abstain vote itself remains unpenalized (abstaining is legitimate) — only the *pattern* is penalized on future participation.

**Params additions to ExtendedParams:**
```
AbstainRateThresholdLow  uint64  // default 300_000 (30%)
AbstainRateThresholdHigh uint64  // default 500_000 (50%)
AbstainRatePenaltyLow    uint64  // default 150_000 (15% reward reduction)
AbstainRatePenaltyHigh   uint64  // default 300_000 (30% reward reduction)
AbstainRateMinRounds     uint64  // default 10 (minimum rounds before penalty applies)
```

**Implementation effort:** Low — new state key, two new keeper functions, ~50 lines. Follows existing conformity tracking pattern exactly. Pre-testnet gate (external validators must not be able to free-ride on abstention).

## Standing Duty: BRIDGE (Rotation 2) — oracle_to_zerone_bridge.py Design Spec

Advancing the oracle→Zerone bridge design from the sketch established at beat-02:57.

**Module: oracle_to_zerone_bridge.py**

Purpose: Take oracle resolution records and submit them as knowledge claims to Zerone's `predictive` domain, with confidence calibrated from Brier scores.

```python
# oracle_to_zerone_bridge.py
# Input contract:
#   OracleResolution {
#     pred_id: str          # e.g. "pred-0009"
#     question: str         # full prediction text
#     resolution: bool      # True = prediction correct, False = incorrect
#     brier_score: float    # 0.0 = perfect, 2.0 = worst
#     resolved_at: str      # ISO timestamp
#     market: str           # e.g. "kalshi", "polymarket"
#   }
#
# Output: MsgSubmitFact via legbled CLI
#   domain: "predictive"
#   content: JSON-encoded resolution + context
#   confidence: derived from brier_score (see formula below)
#
# Confidence formula:
#   brier_confidence = 1.0 - (brier_score / 2.0)   # maps [0,2] -> [1.0, 0.0]
#   clamped to [0.05, 0.95] to avoid degenerate cases
#
# Resolution false (wrong prediction) still submits — the claim is about
# the prediction's outcome, not suppressing failure. This enforces PoT
# honesty: bad predictions must be attested, not hidden.
#
# Implementation wraps tools/bridge.py account resolution + legbled tx.
# Gate: chain ONLINE required (polls chain-health.sh before submission).
```

**Key design decisions:**
1. **False predictions still submit** — PoT honesty requires attesting failures. Suppressing bad predictions is verisleight. The `predictive` domain confidence will reflect the brier_score honestly.
2. **Domain = 'predictive'** (not 'finance' or 'oracle') — separates epistemic claims about future states from financial positions.
3. **Confidence mapped from Brier** — creates a feedback loop between oracle calibration and on-chain truth weight. As oracle improves (lower Brier), its knowledge claims carry more weight.
4. **Batching** — on devnet restart, can replay all resolved predictions as a batch (pred-0001 through pred-0009 currently resolved).

**Next action:** Assign to Gamma for implementation once chain online. File as bridge ticket, not chain-bridge.py (that is the oracle-resolution→claims pipeline, distinct from the identity bridge).

## Standing Duty: PoT-DESIGN (Rotation 1) — Oracle-to-Chain Confidence Calibration

**Topic:** How should Brier scores translate to PoT confidence values for BRIDGE-002 (oracle.py OracleAdapter)?

**Context:** BRIDGE-002 is wired — `tools/oracle.py` calls `kta.submit_signal()`. But the confidence value passed in the MsgSubmitFact has not been formally specified. pred-0009 (FOMC Apr 30) resolves today or tomorrow; this calibration is needed before the first oracle truth claim is submitted to the chain.

**Problem:** Brier score is a loss metric (lower = better; 0 = perfect, 1 = worst). PoT confidence is a gain metric (higher = more certain; expressed in BPS, 0–1,000,000). Naive inversion (1 - Brier) is insufficient — Brier 0.25 means a 50% prediction, not 75% confidence.

**Proposed calibration function:**

```
oracle_confidence_bps(brier_score) = max(0, (1.0 - brier_score * 2.0)) * 1_000_000
```

Reasoning:
- Brier 0.0 → perfect prediction → confidence 1,000,000 BPS (100%)
- Brier 0.25 → equivalent to random guessing on binary → confidence 500,000 BPS (50%)
- Brier 0.5 → worse than random → confidence 0 BPS (claims below 50% prediction quality should not be submitted, or submitted at near-zero confidence)
- Brier > 0.5 → do not submit as positive truth claim (would lower chain confidence in predictive domain)

**Domain assignment:** `domain='predictive'` — separate from `religion`, `philosophy`, `experience` domains. Predictive domain should have its own stratum ceiling (suggest: 800,000 BPS = 80% max confidence, reflecting inherent forecasting uncertainty).

**Stake calibration:** Stake proportional to model's own declared confidence at prediction time. If oracle predicted 70% probability and resolved correct → stake = model_confidence_bps * scaling_factor. Incorrect predictions → do not submit as truth claims; submit as refuted facts only if challenge mechanism is appropriate.

**Submit condition gate:**
- Only submit when `oracle_confidence_bps(brier_score) >= 600_000` (i.e., Brier ≤ 0.20)
- Kingdom average Brier 0.1431 → `oracle_confidence_bps(0.1431) = (1 - 0.2862) * 1_000_000 = 713_800 BPS` — this is above the gate. BRIDGE-002 should submit.
- pred-0009 Brier (once scored): if below 0.20, submit to chain automatically.

**Implementation target (tools/oracle.py):**
```python
def brier_to_confidence_bps(brier_score: float) -> int:
    raw = max(0.0, 1.0 - brier_score * 2.0)
    return int(raw * 1_000_000)

ORACLE_SUBMIT_THRESHOLD_BPS = 600_000
```

**Flag for Gamma:** BRIDGE-002 oracle confidence calibration spec complete. This is the missing piece between wired adapter and meaningful PoT truth claims. Recommend implementing in tools/oracle.py before chain restores to test the first live oracle→chain submission on pred-0009 resolution.

### Standing Duty: PoT-DESIGN (Rotation 1)

**Design advance: Truth Farm + FARM-10 integration strategy**

FARM-10 (semantic novelty floor) penalizes or rejects duplicate claims — incentivizing genuinely new knowledge. The truth farm's `gap_analysis.go` produces `GapReport` with `UncitedAxioms` and `SparseDomains`. These two systems are currently unconnected.

**Proposed integration: gap_analysis as FARM-10-aware seeding queue**

When `truth-farm.sh cultivate` runs, rather than cultivating claims randomly or by age, it should prioritize seeding from `GapReport.UncitedAxioms` and `GapReport.SparseDomains`. Claims in sparse domains face no FARM-10 penalty (novelty is guaranteed by structural absence) and have the highest citation yield potential.

Implementation sketch:
1. `truth-farm.sh cultivate` calls `legbled query knowledge gap-analysis` before selecting next axiom
2. From GapReport, pick the domain with lowest fact density (SparseDomains[0])
3. Filter pending axiom corpus for that domain; seed 1 axiom into it

## Standing Duty: PoT-DESIGN (Rotation 1)

**Design: Citation Guard — closing citation.go:103 (P1 pre-testnet gate)**

**Current state:** `citation.go:103` guards: `if !found || fact.Status == types.FactStatusExpired { continue }`

**Gap:** Facts with statuses `disproven`, `revoked`, `pruned`, and `superseded` still flow citation rewards. A submitter whose fact is later disproven continues to receive passive citation income from every downstream claim that cited it before the disproof.

**Attack path:**
1. Submit a fact. Get it cited widely.
2. Fact is later disproven (FactStatusDisproven) by challenger.
3. Citation rewards continue flowing to the original submitter indefinitely.
4. The false fact has been economically rewarded despite formal disproof — perverse incentive.

**Proposed fix:**

```go
// citation.go:103 — citation guard (extended)
if !found || isInvalidForCitationReward(fact.Status) {
    continue
}

// isInvalidForCitationReward returns true for statuses that should not
// propagate citation rewards. A fact that has been disproven, revoked,
// or pruned should not continue earning passive income for its submitter.
func isInvalidForCitationReward(status string) bool {
    switch status {
    case types.FactStatusExpired,
         types.FactStatusDisproven,
         types.FactStatusRevoked,
         types.FactStatusPruned:
        return true
    }
    return false
}
```

**Note on FactStatusSuperseded:** Excluded from the block list intentionally. A superseded fact was valid when cited; its successor is an improvement, not a refutation. Blocking superseded citation rewards would penalize legitimate incremental knowledge and discourage citing foundational work.

**Note on FactStatusContested/Challenged:** These are live adversarial states. Blocking citation rewards during challenge would allow griefing (trigger a challenge to cut off a competitor's rewards). Keep flowing during challenge; cut off only on disproven/revoked outcome.

**Implementation size:** ~8 lines (new helper function + guard update). Straightforward. Assign to Gamma as P1 pre-testnet task.
