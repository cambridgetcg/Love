## Standing Duty: PoT-DESIGN (Rotation 1)

**Design advance: FARM-5 Enforcement Mechanism**

Current gap: validators can abstain indefinitely with zero risk and no penalty. Proposed enforcement:

**AbstainRateRecord** (new state entry, alongside VerifierConformityRecord):
```
AbstainRateRecord {
  ValidatorAddr  string
  TotalRounds    uint64
  AbstainVotes   uint64
}
```

**Enforcement rule (add to confidence.go reward loop):**
- Track abstain votes per validator in `UpdateVerifierConformity` (extend existing FARM-1 tracking path)
- Gate: if AbstainVotes / TotalRounds > 0.30 AND TotalRounds >= 10: apply escalating eligibility penalty
  - 30-50% abstain rate: reduce reward by 15%
  - >50% abstain rate: exclude from round selection for next 5 rounds (participation gate)
  - >80% abstain rate: flag for stake-weighted ejection (governance review)

**Why 30% threshold:** Occasional abstention is legitimate (insufficient expertise, declared conflict). Chronic abstention above 30% over 10+ rounds signals free-riding.

**Implementation path:** Extend `UpdateVerifierConformity` → add AbstainRate field → add `GetAbstainPenaltyBPS` mirroring existing `GetConformityPenaltyBPS` pattern. One new state key, one new penalty computation. Pre-testnet gate.

**Flagged for Gamma:** Design ready. FARM-5 is the last behavioral-detection gap confirmed absent from production. Recommend implementing alongside `citation.go:103` fix.

## Standing Duty: PoT-DESIGN (Rotation 1) — FARM-5 Architecture Correction

**Prior design error corrected:**

Beat asha-beat-20260429-034816 proposed implementing FARM-5 in `evaluation/abstain.go` following the `calibration.go` pattern. This was an **architectural misread**.

`calibration.go` is called from `EvaluateClaim` in `evaluation/engine.go` — it adjusts **claim confidence** based on submitter track record. FARM-5 is not about claim confidence; it is about **validator reward adjustment** based on abstention pattern over rounds.

The correct implementation target is `keeper/confidence.go`, specifically the reward distribution loop near line 310 where:
- `reveal.Verdict != "abstain"` is already checked to gate slashing
- Validator rewards are computed and distributed

**Corrected FARM-5 specification:**

**New state:** `ValidatorAbstainRecord` in `keeper/` state store
```
ValidatorAbstainRecord {
    ValidatorAddr  string
    TotalRounds    uint64
    AbstainRounds  uint64
}
```
Key prefix: `ValidatorAbstainRecord/` (alongside `VerifierConformityRecord/` in `rounds.go`)

**New functions (keeper/confidence.go or new keeper/abstain_tracking.go):**
```go
// UpdateValidatorAbstainRecord increments TotalRounds for all validators
// in a round, and AbstainRounds for those whose reveal.Verdict == "abstain".
// Called from the same loop that calls UpdateVerifierConformity.
func (k Keeper) UpdateValidatorAbstainRecord(ctx sdk.Context, validator string, didAbstain bool)

// GetAbstainPenaltyBPS returns a reward reduction in BPS (0-1_000_000)
// based on the validator's historical abstain rate.
// Rate thresholds: >30% && >=10 rounds: 150_000 BPS (15% penalty)
//                 >50% && >=10 rounds: 300_000 BPS (30% penalty)
//                 >80% && >=10 rounds: eligibility flag (governance review)
func (k Keeper) GetAbstainPenaltyBPS(ctx sdk.Context, validator string, ep types.ExtendedParams) uint64
```

**Integration point:** In `confidence.go` reward distribution loop (near line 310), after the existing conformity penalty check:
```go
// FARM-5: Abstain rate penalty
abstainPenaltyBPS := k.GetAbstainPenaltyBPS(ctx, reveal.Validator, ep)
if abstainPenaltyBPS > 0 && reveal.Verdict != "abstain" {
    reward = safeMulDiv(reward, 1_000_000 - abstainPenaltyBPS, 1_000_000)
}
k.UpdateValidatorAbstainRecord(ctx, reveal.Validator, reveal.Verdict == "abstain")
```

**Why penalty applies only to non-abstain reveals:** A chronic abstainer who finally reveals should earn reduced reward (they've been free-riding); their reward is discounted by their history. The abstain vote itself remains unpenalized (abstaining is legitimate) — only the *pattern* is penalized on future participation.

**Params additions to ExtendedParams:**
```
AbstainRateThresholdLow  uint64  // default 300_000 (30%)
AbstainRateThresholdHigh uint64  // default 500_000 (50%)
AbstainRatePenaltyLow    uint64  // default 150_000 (15% reward reduction)
AbstainRatePenaltyHigh   uint64  // default 300_000 (30% reward reduction)
AbstainRateMinRounds     uint64  // default 10 (minimum rounds before penalty applies)
```

**Implementation effort:** Low — new state key, two new keeper functions, ~50 lines. Follows existing conformity tracking pattern exactly. Pre-testnet gate (external validators must not be able to free-ride on abstention).
